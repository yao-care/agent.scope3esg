# 03 · 除錯指南

> 系統壞了先看這裡。每個案例：**症狀 → 根因 → 診斷 → 解法**。這些都是實際踩過的雷。
> 通用原則：這台機器對外網路**很不穩**，wrangler/gh/curl 一律包重試 + 加 `dangerouslyDisableSandbox: true`；**單次查詢失敗（404/EOF/ECONNRESET）通常是假的**，重試再判斷。

---

## 通用除錯工具

### A. Worker 即時日誌
```bash
cd scope3-worker
CLOUDFLARE_API_TOKEN=<token> pnpm wrangler tail --format json
```
看 `exceptions[]` 與 `logs[]`。注意：tail 是長連線，網路不穩時自己也會 `fetch failed`，可能要試幾次。輸出是 pretty-printed JSON（跨多行），別用逐行 `JSON.parse`。

### B. 把錯誤細節暫時回傳（tail 連不上時的後備）
在 `src/routes/webhook.ts`（或對應 route）的 handler 包 try/catch，暫時 `return c.json({ error: String(e), message: e.message, stack: e.stack?.slice(0,1000) }, 500)`，部署後觸發，從 HTTP response body 直接讀錯誤。**診斷完務必還原**成 `console.error + 回 generic 500`。

### C. 模擬 installation webhook（不需重新安裝 App）
有 webhook secret 就能自己簽 HMAC 觸發 Worker 跑 `handleInstallation`：
```javascript
// node 腳本；installation id 與 webhook secret 換成實際值
import crypto from 'crypto';
const secret="<GITHUB_WEBHOOK_SECRET>";
const payload=JSON.stringify({action:"created",installation:{id:135631719,account:{login:"yao-care",type:"Organization"}}});
const sig="sha256="+crypto.createHmac("sha256",secret).update(payload).digest("hex");
const res=await fetch("https://scope3-worker.lightman-chang.workers.dev/webhook",{method:"POST",headers:{"x-github-event":"installation","x-hub-signature-256":sig,"content-type":"application/json"},body:payload});
console.log(res.status, await res.text());
```

### D. 查 D1 / repo 狀態
```bash
CLOUDFLARE_API_TOKEN=<token> pnpm wrangler d1 execute scope3 --remote --json --command "SELECT * FROM tenants"
gh api /repos/yao-care/scope3-inventory/git/trees/HEAD?recursive=1 --jq '.tree[].path'
gh api /orgs/yao-care/installations --jq '.installations[] | {id, app_slug, permissions}'
```

## 案例庫

### 1. 安裝後沒建 repo / 安裝 webhook 回 500 ⭐最常見
- **症狀**：安裝 App 後 org 沒出現 `scope3-inventory`；模擬 webhook 回 500。
- **根因（按機率）**：
  1. **production D1 沒套 migration** → 錯誤 `no such table: tenants`。`createTenantRepo` 其實成功建了 repo，但 `insertTenant` 失敗 → 整體 500。**CI deploy 不會自動套 migration**。
  2. App 缺 `Administration` 權限 → 建 repo 那步 403。
  3. webhook secret 不符 → 簽章驗證 401（不是 500）。
- **診斷**：用工具 B 取得確切錯誤訊息。
- **解法**：
  - `no such table` → `cd scope3-worker && CLOUDFLARE_API_TOKEN=<t> pnpm wrangler d1 migrations apply scope3 --remote`
  - 缺權限 → App 設定頁補 `Administration: Read and write` 後核准。
- **注意**：repo 可能「其實已建好」但你查 404——那是網路假象（見案例 3）。先用工具 D 確認 repo 真實內容。

### 2. GitHub App 認證失敗 / 換 installation token 失敗
- **症狀**：`getInstallationOctokit` 報錯、JWT 相關錯誤、OAuth 換 token 失敗。
- **根因**：private key 格式錯。GitHub 下載的 `.pem` 是 **PKCS1**（`-----BEGIN RSA PRIVATE KEY-----`），但 Cloudflare Workers 的 Web Crypto **只接受 PKCS8**（`-----BEGIN PRIVATE KEY-----`）。
- **解法**：
  ```bash
  openssl pkcs8 -topk8 -inform PEM -outform PEM -nocrypt -in original.pem -out pkcs8.pem
  cat pkcs8.pem | CLOUDFLARE_API_TOKEN=<t> pnpm wrangler secret put GITHUB_APP_PRIVATE_KEY
  ```
  確認轉換後第一行是 `-----BEGIN PRIVATE KEY-----`。

### 3. 查詢回 404 / EOF / ECONNRESET（網路假象）
- **症狀**：`gh api /repos/...` 回 404 或 `EOF`；`curl` 回 `SSL_ERROR_SYSCALL`；`node fetch` 回 `ECONNRESET`。
- **根因**：這台機器對外網路不穩，**單次失敗常是假的**，不代表資源不存在。曾因此誤判「repo 沒建出來」而白繞一大圈。
- **解法**：
  - 所有對外命令加 `dangerouslyDisableSandbox: true`（沙箱會擋連線）。
  - 包重試迴圈：`n=0; until <cmd>; do n=$((n+1)); [ $n -ge 8 ] && break; sleep 3; done`。
  - 重要結論（如「repo 不存在」）至少用兩種方式 / 重試多次確認後才下判斷。

### 4. 重複安裝 / webhook 重送 → 500
- **症狀**：第二次觸發 installation 報 `name already exists`（建 repo）或主鍵衝突（insertTenant）。
- **根因**：非冪等。
- **現況**：兩者皆已修為 idempotent——`createTenantRepo` 遇 422 改 GET 現有 repo node_id；`insertTenant` 用 `onConflictDoUpdate`。若再發生，先確認 `src/github/repo.ts` 與 `src/db/queries.ts` 這兩段沒被改壞。

### 5. 既有租戶 repo 缺新模板檔
- **症狀**：在 `tenant-template/` 新增了檔案（如 workflow），但既有租戶 repo 沒有。
- **根因**：`createTenantRepo` 對「已存在的 repo」idempotent 跳過，不補新檔。
- **解法**：手動補，例如：
  ```bash
  CONTENT=$(openssl base64 -A -in tenant-template/.github/workflows/config-sync.yml)
  gh api -X PUT /repos/yao-care/scope3-inventory/contents/.github/workflows/config-sync.yml \
    -f message="chore: add workflow" -f content="$CONTENT"
  ```

### 6. R2 / 部署相關
- **`error 10042` 建 bucket 失敗**：R2 未啟用，需在 Cloudflare Dashboard 手動啟用（無 API），啟用後 `wrangler r2 bucket create scope3-files`。
- **部署失敗 `R2 bucket 'scope3-files' not found` (10085)**：bucket 沒建（同上）。R2 binding 在 `wrangler.toml`，bucket 不存在則 deploy 失敗。

### 7. GitHub App「Subscribe to events」找不到
- **症狀**：Permissions & events 頁找不到事件勾選區。
- **根因**：要先在 **General → Webhook** 啟用 webhook（勾 Active），且權限要先 **Save**，事件區才出現。
- **重點**：建 repo 靠 `installation` 事件，**GitHub 自動送、不需訂閱**。所以這個區塊找不到也不影響核心安裝流程。

### 8. config.yml 改了沒自動產生供應商連結
- **症狀**：編輯 config.yml 後 `supplier-links.md` 沒更新、沒產 token。
- **根因**：本 App 沒訂閱 `push` 事件（刻意，繞過難找的 Subscribe to events）。改用租戶 repo 內的 `config-sync.yml` Action（on push config.yml）呼叫 Worker `POST /api/v1/config-sync/:org`。
- **檢查**：① 租戶 repo 有沒有 `.github/workflows/config-sync.yml`（既有 repo 可能要補，見案例 5）；② D1 `tenants` 有沒有該 org 記錄（端點靠它查 installation_id）；③ 手動測端點：`curl -X POST https://scope3-worker.lightman-chang.workers.dev/api/v1/config-sync/yao-care`（應回 `{"ok":true}`）。

### 9. 排放量計算失敗（水/單位）
- **症狀**：核定後 calculate 留言「單位無法轉換」，submissions.json 沒更新。
- **根因**：活動類型的單位與排放係數分母單位不相容，且 `convertUnit` 無對應規則。water 已統一用 `ton`（1 m³≈1 ton）。
- **檢查**：`tenant-template/scripts/lib.mjs` 的 `UNIT_RULES`、`tenant-template/data/emission-factors.json` 的係數 `unit`、`src/routes/submit.ts` 表單單位選項——三者的 activity_type 與單位要一致。

### 10. admin 管理介面登入問題
- **症狀**：`/admin/:org` 登入卡住、callback 失敗。
- **根因/檢查**：
  - Callback URL 要在 App 設定填 `<WORKER_URL>/admin/callback`。
  - `GITHUB_APP_CLIENT_ID`、`GITHUB_APP_CLIENT_SECRET`、`SESSION_SECRET` 三個 secret 要都設。
  - callback 會驗證登入者是該 org 成員（`GET /orgs/{org}/memberships/{user}` 須 active）；非成員回 403。
  - 用工具 A（tail）看 `/admin/callback` 的錯誤。
